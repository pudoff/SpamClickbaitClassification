## 3. Разметка, очистка и сплиты

### 3.1. Проблемы текущего датасета (подробно — `01` R-36…R-40)

| Наблюдение (проверено скриптом 01.10.2026) | Риск | Мера |
|---|---|---|
| Медиана длины: `normal` — 75 символов, `spam` — 536, `clickbait` — 58; доля текстов со словами латиницей ≥ 4 букв: 0.33, 0.67, 0.05 | Модель различает **источник и длину**, а не смысл; короткий голосовой спам будет похож на `normal` | Длинные тексты — фрагменты по 10–80 слов; оценка по корзинам длины; основной тест — голосовые |
| Топ-признаки кликбейта (`model.ipynb`, ячейка 25): «адель», «пугачевой», «buzzfeed», `num фотографии` | Модель выучила темы и шаблоны заголовков | Групповой сплит по шаблонам; срез без знаменитостей |
| 596 групп текстов, совпадающих после нормализации; 9 текстов с разными метками | Утечка между train и test, шум меток | Дедупликация по нормализованному тексту; конфликты — на ручную разметку |
| Случайный `train_test_split` после удаления только точных дублей | Завышенная оценка (macro-F1 0.935 в ноутбуке) | §3.3 |
| Цифры в текстах (`NUM`) и в выходе ASR | Расхождение признаков при обучении и инференсе | `v3_e2e_rnnt` с цифрами; E-2a |

### 3.2. Разметка голосовых

- Label Studio: аудио, расшифровка ASR, эталонная расшифровка (для WER), метка, атрибуты `fraud_suspected` и «неразмечаемо».
- Метка сценария `/record` — только подсказка. Итоговую метку ставят двое, расхождения решает третий.
- Каппа Коэна ≥ 0.70 на партию. Если ниже — инструкция дорабатывается.

### 3.3. Сплиты без утечек

- **Текст.** `StratifiedGroupKFold`. Группа — кластер близких дубликатов (MinHash по словесным 3-граммам, Жаккар ≥ 0.8) и «шаблон заголовка» (числа и имена собственные заменены). Результат: text-train 80 % / text-test 20 % по группам.
- **Голос.** Группа — диктор. Дикторы voice-holdout не встречаются ни в voice-calib, ни в voice-train. Сценарии holdout берутся из шаблонов, которых нет в text-train.
- **TTS** только в train.
- voice-holdout замораживается первым (`holdout-v1`). Ошибки разбираются на voice-dev.
- `check_leakage.py` — обязательный шаг `dvc repro`, при нарушении шаг падает.

## 4. Метрики

| Метрика | Набор |
|---|---|
| Macro-F1 среди `classified`, P/R по классам, precision и recall `spam`, precision `clickbait` | voice-holdout (основной), text-test |
| FPR `normal → spam` | voice-holdout |
| Coverage, доли отказов по причинам, корректность `not_classified` | voice-holdout |
| ECE (10 бинов), диаграмма надёжности | voice-calib, voice-holdout |
| WER и CER ASR | voice-holdout с эталонными расшифровками (≥ 150) |
| Срезы: длительность (< 5 с, 5–30 с, > 30 с), «прочитано» или «пересказано», шум, диктор; для текста — корзины длины | Оба |
| Бутстрэп-ДИ 95 % (1000 повторов) | Все основные |

Accuracy как главная метрика не используется. В `model.ipynb` `GridSearchCV` оптимизирует `f1_weighted` — рекомендуется перейти на `f1_macro`.

**Confidence, калибровка, дрейф и качество — разные вещи:**

- **Confidence** — выход модели для одного ответа.
- **Калибровка** — согласие confidence с частотой правильных ответов. Проверяется ECE на размеченных данных.
- **Дрейф** — изменение входов. Видно без разметки, но падения качества не доказывает.
- **Качество** — только метрики на свежей эталонной разметке.

Низкая средняя confidence может означать новые темы, а не ошибки. Высокая confidence не гарантирует правильности. Дрейф запускает разметку, а не переобучение.

## 5. Эксперименты

| ID | Эксперимент | Критерий выбора |
|---|---|---|
| E-0 | Мажоритарный класс; словарь триггеров | Нижняя граница |
| E-1 | ASR: GigaAM `v3_e2e_rnnt`, `v3_e2e_ctc`, `v3_rnnt` (+ числа в цифры), Whisper `large-v3-turbo`; E-1b — GigaAM в ONNX | WER на voice-holdout, затем macro-F1 конвейера; время p95 на сервере |
| E-2 | Модель 2 из `model.ipynb` на **групповом** text-test и на voice-holdout; затем TF-IDF + LR с калибровкой (sigmoid) и подбором `C` по `f1_macro` | Macro-F1 на voice-holdout |
| E-2a | Обучение на исходных текстах, на транскриптах TTS → ASR и на их смеси | Δ macro-F1 на voice-holdout — ответ на «усложнение» кейса |
| E-2b | Разбиение длинных спам-текстов на фрагменты по 10–80 слов | Δ recall `spam` на коротких голосовых |
| E-3 | rubert-tiny2 на транскриптах | Прирост с непересекающимися ДИ или p < 0.05 (парный бутстрэп) |
| E-4 | Гибрид: текст + эмбеддинги GigaAM `v3_ssl` | Прирост на voice-holdout без роста FPR |
| E-5 | Подбор τ и τ_spam на voice-calib | Precision `spam` ≥ 0.85 при максимальном coverage |

Обязательный отчёт для курса — **E-2a**: «без TTS / с TTS» на реальных голосовых с ДИ.

## 6. Ворота допуска и выпуск

Переобучение создаёт кандидата. Выпуск возможен только после всех шагов.

1. **Данные:** схема, дубликаты, `check_leakage.py`, каппа ≥ 0.70, отчёт баланса классов.
2. **Технические тесты:** нет NaN, сумма вероятностей = 1 ± 1e-6, детерминизм, загрузка в образ `inference-api`, одинаковая `clean_text` при обучении и в сервисе.
3. **Качество** (пороги `02` §10, voice-holdout):
   - macro-F1 ≥ 0.75; precision `spam` ≥ 0.85; recall `spam` ≥ 0.70; precision `clickbait` ≥ 0.70;
   - FPR `normal → spam` ≤ 5 %; coverage ≥ 0.75; ECE ≤ 0.08;
   - `not_classified`: ≥ 95 % записей без речи, ≥ 90 % не русских записей;
   - text-test (групповой): macro-F1 ≥ 0.85; WER ≤ 20 %;
   - при замене действующей модели — не хуже неё по macro-F1 и precision `spam` с учётом ДИ, ни один срез не просел больше чем на 5 п. п.
4. **Проверка в локальном Docker:** `docker compose --profile core up` с тестовым ботом (отдельный токен), прогон T-BOT-* и T-CON-*.
5. **Производительность на сервере:** T-PERF-01, p95 ≤ 15 с для голосовых ≤ 60 с.
6. **Согласование:** отчёт в `docs/releases/<версия>.md`; «за» не меньше 3 из 4, обязательно R-ML и R-ASR.
7. **Развёртывание на сервер:**
   - алиас `production` в MLflow переводится на новую версию, `previous` — на старую;
   - на сервере в `.env` меняются `CLASSIFIER_MODEL_VERSION` и `DECISION_POLICY_VERSION`;
   - `docker compose pull && docker compose --profile core up -d inference-api`;
   - при старте сервис проверяет SHA-256 артефакта и 20 эталонных примеров; при несовпадении `/v1/health` = 503, и выпуск откатывается.
8. **Наблюдение:** 7 дней — `/stats`, доля «👎 Неверно», ошибки, время.
9. **Откат:** вернуть `.env` на `previous` (или предыдущий тег образа) и перезапустить, ≤ 10 мин. Поводы — ошибки > 5 % проверок за сутки, coverage < 0.6 или деградация, подтверждённая разметкой.

Отзывы «👎 Неверно» в обучение не попадают. Если запись есть в датасете, она уходит в Label Studio кандидатом на двойную разметку.

## 7. Измерение производительности

- **Стенд:** сервер проекта (A-01) с прод-конфигурацией. Локальный Docker используется только для функциональных тестов.
- **Набор:** 60 голосовых из voice-dev длительностью 5, 15, 30, 60, 120 и 300 с.
- **T-PERF-01:** последовательно, по 10 повторов на длительность; участки из `timings_ms` и время «отправка → ответ бота».
- **T-PERF-02:** 4 одновременных пересылки — время в очереди.
- **T-PERF-03:** GigaAM на CPU против ONNX (и против GPU, если он есть на сервере).
- **Результат:** таблица участков из `03` §9. Цели подтверждаются или пересматриваются с записью в журнал.

## 8. Версии, CI, развёртывание

- **Код:** git (публикация и CI на GitHub — по решению владельца репозитория, Q-10).
- **Данные:** DVC. Хранилище на сервере, доступ по SSH; копия на внешнем диске. `holdout-vN` — теги.
- **Модели:** реестр MLflow на сервере (`asr`, `lid`, `classifier`, `decision-policy`); в ответе — `имя@версия`. Локально модели подтягиваются `make models` (DVC pull).
- **Проверки перед слиянием** (`make check`; на GitHub Actions — если включат): ruff, pytest, валидация OpenAPI (`tools/validate_openapi.py`), тесты бота с фиктивным Bot API, сборка образов.
- **Окружения:**
  - **dev** — у каждого участника `docker compose --profile core up` с собственным тестовым ботом (токен от @BotFather), локальный `.env`;
  - **prod** — сервер, `docker compose --profile core up -d` с прод-ботом, образы с тегом git SHA;
  - в обоих окружениях один и тот же `compose.yaml`, различаются только `.env`.
