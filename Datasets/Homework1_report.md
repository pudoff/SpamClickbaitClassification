# Отчёт по Task1: классификация спама и кликбейта

**Команда:** «Великолепная четверка». **Дата:** 09.10.2026. **Ревизия:** `76c0233`.

**Репозиторий:** [pudoff/SpamClickbaitClassification](https://github.com/pudoff/SpamClickbaitClassification). **Полное описание данных и экспериментов:** [dataset_description.md](dataset_description.md), [HTML](dataset_description.html).

## Задача и данные

Начальный этап проекта — пока только на текстовом датасете,  классификация сообщения в три категории: **0 — обычное, 1 — спам, 2 — кликбейт**. В полном кейсе текст должен получаться из голосового сообщения Telegram через ASR; TTS используется для подготовки синтетического аудио. Этот отчёт описывает текстовую классификацию.

Собранный датасет содержит  **641 737 записей с допустимыми метками**. Распределение до очистки: обычные **370 272 (57,70%)**, спам **157 100 (24,48%)**, кликбейт **114 365 (17,82%)**. Медиана длины — **113 символов**, среднее — **370,71**, максимум — **5 718**. Спам обычно длиннее, кликбейт короче; длина может отражать происхождение данных, а не только смысл категории.

Основные проблемы: около **28,85% повторных записей**, конфликтующие категории, повреждённые фрагменты (перенос строк и тд) и неоднородный перевод. Для экспериментов текущие ноутбуки удалили **185 128** повторов и **1 061** уникальную пару из конфликтных групп; осталось **455 548** примеров. Стратифицированный разделение 80/20, seed=42: **364 438 train / 91 110 test**. 

По сохранённому эвристическому профилю RNN **14,68%** записей имеют один из флагов: мало кириллицы, текст в верхнем регистре ( КАПС ), URL либо повтор слова; **85,32%** не имеют этих флагов. Это не доли доказанно плохой/хорошей разметки: ссылки и КАПС могут быть полезными признаками спама. 

## Предобработка и выбор методов

Реализован один метод предобработки — **нормализация регулярными выражениями**: обработка HTML/упоминаний, маскирование ссылок и чисел, lowercase, `ё→е`, удаление пунктуации/эмодзи, нормализация пробелов. Метод сокращает случайные вариации текста. Обнаружены отдельные дефекты URL/NUM и пустых входов; их нужно исправить согласованно для обучения и сервиса.

Выбраны методы вебинара 4 **без трансформеров**:

- **TF-IDF + LogisticRegression** как воспроизводимая базовая модель. Словные n-граммы описывают сочетания слов; символьные потенциально повышают устойчивость к окончаниям, опечаткам и шаблонам. Word+char FeatureUnion — признаки одного классификатора.
- **Гибрид BiGRU с attention pooling, символьной CNN и поверхностными признаками** для проверки пользы последовательного контекста и локальных паттернов. Около 8,11 млн параметров; три эпохи AdamW с scheduler и clipping.
- **Отдельный char-CNN** как дополнительный классификатор для смешивания вероятностей. Из трёх кандидатов перебор выбрал веса **RNN 0,8 / CNN 0,2 / TF-IDF 0,0**: итоговый ансамбль имеет два действующих участника.

## Полученные результаты

| Модель | Accuracy | Macro-F1 | Weighted-F1 |
| --- | ---: | ---: | ---: |
| TF-IDF word + LR | 0,7948 | 0,7715 | 0,8039 |
| TF-IDF word+char + LR, контроль | 0,8093 | 0,7822 | 0,8165 |
| Лучший текущий LR run_6 | 0,8394 | 0,8087 | 0,8432 |
| Отдельный char-CNN | 0,8452 | 0,7961 | 0,8408 |
| Гибридная RNN | 0,8630 | 0,8242 | 0,8620 |
| **Ансамбль RNN + CNN** | **0,8677** | **0,8282** | **0,8661** |

Macro-F1 учитывает все классы равноправно и используется вместе с accuracy из шкалы задания. Для ансамбля F1 обычных **0,8950**, спама **0,9203**, кликбейта **0,6695**. Прирост accuracy к отдельной RNN — около **0,47 п.п.**

**Результаты предварительные:** после нормализации совпадения с train найдены у **3 267 тестовых строк (3,586%)**; checkpoint RNN выбирался по test. Dev для ансамбля выделяется после обучения нейросетей на всём train, а из-за перестановки результатов разбивки (spilt) содержит 90% train. Значит, подбор весов пока не удовлетворяет условию независимой validation. 

Необходимо повторить обучение на групповом fit/dev/test и оценить результат на независимом holdout. Можно еще также подчистить датасет.

## Анализ ошибок и обработка результатов

Ансамбль допустил **12 055 ошибок**. Основная путаница: **4 943 кликбейта→обычные** и **3 673 обычных→кликбейт**, вместе **71,47% ошибок**. На **2 097 сообщениях ≤3 raw-слов** accuracy **0,8026**, macro-F1 **0,6279**, F1 кликбейта **0,3570**. Это трудная подгруппа, но она не составляет большинство всех ошибок.

## Вывод и следующий этап

Реализованы предобработка, классификация изученными методами, усреднение вероятностей, анализ ошибок и постобработка. Лучший сохранённый результат **86,77%** численно соответствует диапазону ≥85%, но <90% из Task1;  Дополнительный ансамбль реализован технически, но можно подкорректировать подбор весов на валидации.

Приоритет — проверить воспроизводимость, утечки и сохранить полный пакет RNN/CNN со словарями. Далее — интеграция выбранной модели в сервис на FastAPI, голосовой тест ASR и реализация TTS/Telegram полного кейса.
